Ausführliche Beschreibung

Parametrierbarer Classic-CAN-Sender und -Empfaenger fuer KIT_XMC14_2Go.

Die ID identifiziert eine Botschaft, nicht die Adresse eines Geraetes. CANlib benutzt CAN-Knoten 0 und Message Objects 0 (RX) und 1 (TX) exklusiv. I2C und OLED werden weiterhin durch DAVE initialisiert. Es ist keine zusaetzliche CAN-DAVE-APP noetig.

bool CANLIB_Receive ( CANLIB_Message_t *  message)

Fragt ohne Warten auf eine neue Botschaft das Empfangsobjekt ab.

Parameter
[out]messageGueltiger Ergebnispuffer; wird nur bei true beschrieben.
Rückgabe
true fuer eine neue passende Datenbotschaft, andernfalls false.

Hoechstens drei Leseversuche verhindern eine Endlosschleife bei gleichzeitigem Hardwareempfang. Im Hauptprogramm moeglichst oft aufrufen. Ein einzelnes Hardwareobjekt speichert den neuesten Frame; waehrend langsamer Displayzugriffe koennen aeltere Frames ueberschrieben werden. Dies ist eine Anzeige der letzten Botschaft, kein verlustfreier CAN-Logger.

CANLIB_TxResult_t CANLIB_Send ( const uint8_t *  data,
uint8_t  length 
)

Startet eine Classic-CAN-Datenbotschaft mit CANLIB_TX_ID.

Parameter
[in]dataZeiger auf mindestens length Bytes; darf nicht NULL sein.
[in]lengthAnzahl Nutzdatenbytes von 0 bis 8 (gleich DLC).
Rückgabe
ACCEPTED bei angenommenem Auftrag, BUSY bei belegtem Objekt, ERROR bei ungueltigen Parametern oder nicht betriebsbereitem CAN.

Kopiert die Daten sofort; der Aufrufer darf seinen Puffer danach wiederverwenden. Wartet nicht auf Bus oder ACK und hat keine Warteschlange. Bei BUSY/ERROR bleibt der bisherige Auftrag unveraendert. Die Hardware wiederholt fehlgeschlagene Uebertragungen automatisch. Ohne ACK kann das Objekt dauerhaft belegt bleiben. Bus-off erfordert einen Board-Neustart.

Zu beachten
Nur aus der Hauptschleife aufrufen, nicht gleichzeitig aus Interrupts. ACCEPTED bestaetigt nur die Uebergabe, nicht die erfolgreiche Busuebertragung.
